# Codex 后台性能监测

关闭网页不影响采集，无需把窗口一直放在前台。

## 使用

双击「启动 Codex（代理）.cmd」：按 1 启动 Codex，后台连接监视与性能采集自动跟随；按 2 查看网络、字速、耗时和 token；按 0 退出。查看面板复用已有服务，不重启 Codex 或 VPN。「打开性能监测面板.cmd」可直接打开面板。

需要 PowerShell 7、Node.js 20+，无额外 npm 依赖。服务运行于当前 Windows 登录会话，不设开机自启。能力自检、评分与基线比较已移除，不额外调用模型。

在解压目录预检：

~~~powershell
pwsh -NoProfile -File '.\Start-CodexPerformanceMonitor.ps1' -DryRun
~~~

跳过本次自动性能采集，保留连接监视：

~~~powershell
pwsh -NoProfile -File '.\Start-CodexWithProxy.ps1' -NoPerformanceMonitor
~~~

该开关不停止已运行服务，本次新启动不接入实时采集；固定代理入口仍需要 Node.js。-NoWatchdog 只控制连接监视，实时采集独立核对主进程身份。

## 网络诊断

顶部状态只表示网页与本地采集器连接正常。外部网络分别检查本地、本地代理、VPN / 出口、OpenAI 路径，显示检测时间、延迟、失败步骤、依据与建议。过期或离线不保留绿灯，最近 20 条变化帮助核对恢复。

- 系统信息约每 30 秒只读核对。依据监视进程参数、Codex 路径与启动时间确认实际入口；有 relay 时显示固定入口与当前上游。无匹配会话时注明“当前系统代理，未绑定 Codex”；分协议设置采用 HTTPS 入口。
- 本地端口约每 3 秒检查；直连、同入口代理与 OpenAI 边缘探测正常时约每 30 秒、待核对时约每 10 秒。远端单次最多 8 秒，各环节独立，不依赖网页。
- 只对 Windows 连通性对照目标、Microsoft、chatgpt.com 静态目标发送 HEAD，不携带认证、不调用模型、不读取响应正文，产生少量流量。
- 403、429、5xx 是收到的限制、限流、错误响应，不等于断网。代理 CONNECT 拒绝与目标响应分开显示；无默认路由也可能是 VPN 拆分路由。
- 本地拒绝或已核对 relay 未就绪可以定位；VPN / OpenAI 路径通常只能判断“疑似”。不同目标可能走不同规则，边缘探测不能证明模型、账户、WebSocket 或流式输出正常。

## 统计口径

- 首 token 耗时采用已有 time_to_first_token_ms，可能含服务等待与推理，不是网络延迟。
- 输出/推理 token 是该轮累计用量，重复通知不重复累计；输出可能含推理或工具，不等于可见文字数。
- 整轮 token/s 是输出量除以整轮耗时，含思考、工具与网络等待，不是实时纯生成速度。
- 消息输出阶段均速是已完成 AgentMessage 的 Unicode 码点数除以消息生命周期，单位字符/s。优先最终回答，否则最近中间回复；之前的等待不计入，消息期间停顿可能计入。缺时间、倒序或不足 1 秒显示原因与 —。
- 实时接收速度是最近 3 秒收到的 AgentMessage Unicode 码点数除以 3，单位字符/s。emoji 按码点，空格与换行计入；不是精确 token/s 或服务端解码速度。观测到输出后暂停可显示 0；未观测、完成、心跳超过 5 秒或离线显示 —。
- thread 与 turn 共同核对模型，未知模型单列。缺字段不当 0，未结束任务不伪造最终平均。
- 查看最近三天目录并跟踪活动文件，最多 80 文件、200 轮；每次最多 8 MiB、每文件 1 MiB，超过 256 KiB 的单条记录跳过并提示不完整。

同模型趋势与历史只反映本机可见记录，不能证明服务端隐藏模型切换。两项文字速度和原 token 用量、整轮 token/s 同时保留。

## 实时接入

通过 CODEX_CLI_PATH 在面板版入口下一次正常启动接入。旧桌面会话不能事后附着私有 stdio，显示“下次正常启动后生效”；无需立即退出聊天。

转接器保留 CLI 参数与 stdin/stdout/stderr 字节，旁路解析增量。准备失败回退原 CLI，计数写入失败不阻止聊天，不创建额外 app-server 或模型请求。每个接入 CLI 另有原生转接器与 Node 透传，最多 20 条计数消息，不保存文字。

过期只表示本地快照超过 5 秒未更新，不代表 OpenAI 故障。临时文件占用或写入失败按 250–2000 毫秒退避重试，错误仅含代码、步骤与时间。目录变链接或身份不符时停止采样并说明原因。

源码维护工具可核对进程 PID、路径和启动时间，恢复已经接入的旁路，不重启聊天；不能附着从未接入的旧会话，恢复后从当时累计，不补算中断文字。工具要求 Node.js 22+，不随日常 ZIP 提供。

## 本地数据与资源

网页仅由 127.0.0.1 提供，无第三方资源；HTTP 只读，拒绝跨站和写入。采集解析本地日志/输出，仅保存时间、计数、模型和状态元数据，不复制/持久化聊天或工具正文，不修改认证、全局配置、VPN 或当前聊天。

状态位于本目录 runtime\performance-<目录标识>\service.json。实时绑定和随机启动目录位于 generation 子目录；读取前核对主进程，旧启动不参与当前测速。网页 API 不公开可执行文件路径或私有启动标识。

后台服务、浏览器、连接监视器、固定入口、实时透传应分开计算内存；服务内存不是总占用，实际值随会话与 Node 改变。两下载包共享既有 Codex 数据，不代表两套独立应用同时运行。

开发阶段采用合成日志、本地套接字和假 CLI 验证统计、网络分类、只读 HTTP、页面及实际原生转接链路；无模型额度。恢复夹具验证分享锁释放后重试、旁路恢复、字节透传、身份及调试端口关闭。源码命令见仓库 docs/开发验证说明.md。未测试真实任务断网连续性。
