# 从源码构建与离线验证

仓库 tag 的源码不含编译 EXE。日常用户下载 Release Windows ZIP 即可，无需下面的开发环境。

## Windows helper：Go 1.24+

源码沿用 macOS/native-launcher 命名，包含 Windows 辅助分支和测试：

~~~powershell
Push-Location -LiteralPath '.\macOS\native-launcher'
go test ./...
go vet ./...
go build -trimpath -ldflags '-s -w' -o '..\..\VpnRecoveryHelper.exe' .
Pop-Location
~~~

## 实时转接器：Windows x64 MinGW-w64

~~~powershell
g++ -std=c++17 -O2 -municode -static -static-libgcc -static-libstdc++ -o '.\bridge\CodexGenerationForwarder.exe' '.\bridge\CodexGenerationForwarder.cpp'
~~~

该 C++ 文件负责进程和标准流透传，不是 provider/profile 转接器，不修改官方安装目录。

Release 中的现成转接器使用 GCC 8.1.0 / MinGW-w64 构建，未在本次发布重建。GCC、MinGW-w64 与 winpthreads 原文许可置于 licenses；[GCC 运行时异常](https://www.gnu.org/licenses/gcc-exception-3.1.html)说明编译器运行时相关条款。

## 浏览器与完整夹具

自行安装开发验收用 Playwright，它不是日常依赖。PLAYWRIGHT_MODULE_PATH 指向自装模块的绝对路径，例如：

~~~powershell
$env:PLAYWRIGHT_MODULE_PATH = (Join-Path (Get-Location) 'node_modules\playwright\index.mjs')
node '.\performance-monitor\verify-browser.mjs'
node '.\performance-monitor\verify-task-search.mjs'
node '.\performance-monitor\verify-generation-integration.mjs'
node '.\performance-monitor\verify-generation-recovery.mjs'
~~~

使用已安装 Microsoft Edge，不提交 node_modules、生成 diagnostics/runtime 或本机日志。

tests/fixtures/generation-bridge-before-retry.mjs 是复现旧写入失败行为的纯源码夹具，验收复制为临时入口；无会话、认证或本机状态。完整验收只用假 CLI，不调用真实 Codex CLI/模型，不改系统代理或启停 VPN。

夹具验证指定解析、进程、透传与页面行为，不证明真实断网任务连续性。
