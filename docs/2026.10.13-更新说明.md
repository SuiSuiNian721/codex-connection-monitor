# 2026.10.13 面板版：后台窗口唤起与缓存复用修复

本次解决“任务管理器里有 Codex，却看不到窗口，启动器仍提示已经运行”的问题。

- **再次点击可以请求显示原窗口。** 启动器会核对默认配置的后台实例，再通过 Codex 自带的单实例机制唤起窗口，保留已有进程和会话。
- **启动结果以窗口为准。** 只有进程出现时会继续等待；窗口可用后显示“窗口已打开”。等待期间每约 5 秒显示进度，超过 90 秒仍未就绪会明确提示启动未完成。
- **缓存不再与应用清理逻辑冲突。** 启动器的 CLI 副本改放独立目录，同版本校验通过后复用，升级时保留旧副本并准备新文件。
- **启动慢也能保留后台监测。** 等待超时后，为核实属于本次启动的主进程保留连接监视、性能采集与实时输出绑定；窗口状态仍显示未完成。
- **独立配置不会被误开成默认窗口。** 使用独立配置目录或无法确认身份的实例，会提示从原会话入口打开。

面板原有的四项网络诊断、实时字速、消息均速、首 token 等待、用量、并行任务检索及同模型历史继续提供。

完整解压新版后，双击「启动 Codex（代理）.cmd」：按 `1` 启动，按 `2` 查看面板。需要启用新版代理与采集接线时，保存当前工作并正常退出 Codex，再从新版目录启动。

同版本的本地缓存可以复用；Codex 自身升级下载仍由应用处理。窗口打开也不代表网络连接已经恢复，连接状态可在面板中查看。
